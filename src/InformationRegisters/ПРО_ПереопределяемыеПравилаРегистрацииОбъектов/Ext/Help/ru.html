Справочная информация: Фильтры правил регистрации объектов

Назначение подсистемы

Подсистема «ПРО управление регистрацией данных» предназначена для настройки правил обмена данными между информационными базами без изменения основной конфигурации.

Типовой сценарий использования: при обмене через Конвертацию данных 3 в конфигурации уже настроены типовые правила регистрации объектов. Однако иногда эти правила работают не так, как требуется для конкретного узла обмена. Вместо того чтобы дорабатывать конфигурацию, вы можете переопределить правила прямо в режиме 1С:Предприятия.

Основные настройки

1. Настройка узла обмена

Для каждого узла обмена можно включить или отключить использование переопределений:

  • Использовать переопределение регистрации — если выключено, система работает по типовым правилам; если включено, применяются ваши настройки. По умолчанию всем объектам устанавливается запрещающее правило.

2. Фильтры правил регистрации объектов

Это основной регистр, где хранятся настройки правил обмена для конкретных объектов (справочников, документов, регистров).

Параметры фильтра

Узел информационной базы — узел плана обмена, для которого настраивается правило.

Объект регистрации — объект метаданных (справочник, документ и т.п.), для которого настраивается правило.

Настройки правила

Регистрация объекта разрешена — простой способ управления:

  • Включено — объект будет регистрироваться для обмена
  • Выключено — объект не будет регистрироваться

Это ПОД — справочное поле, показывающее источник правила:

  • Да — правило взято из настроек менеджера обмена через универсальный формат
  • Нет — правило взято из состава плана обмена (объект метаданных)

Применить собственное правило — включите, если нужна сложная логика вместо простого «да/нет»

Исполняемый код — программный код на языке 1С для реализации сложных условий регистрации (см. примеры ниже).

Пример исполняемого кода:

Если СтрНайти(ДанныеИБ.Наименование, "Владимир Владимирович Пу") > 0 Тогда
    ФильтрПройден = Истина;
КонецЕсли;

3. Дополнительная регистрация связанных объектов

Собственное правило может заявить, что вместе с объектом на текущий узел нужно зарегистрировать связанные объекты — например, присоединённые файлы документа. Для этого в коде правила вызывается метод ПРО_ИсполняемыйКод.ЗарегистрироватьСвязанные(ДополнительнаяРегистрация, Ссылки, ТолькоНевыгруженные):

  • ДополнительнаяРегистрация — переменная контекста правила, передаётся как есть;
  • Ссылки — ссылка, массив или фиксированный массив ссылок; Неопределено, Null и пустые ссылки пропускаются;
  • ТолькоНевыгруженные — Истина: только объекты, которые ещё не отправлялись на узел и не сопоставлялись с ним.

Регистрацию выполняет расширение при записи объекта и при ручной регистрации ссылки на узел (обработка «Регистрация изменений для обмена данными»), и только если объект в итоге регистрируется на узел (ФильтрПройден = Истина и узел не исключён). При выгрузке, удалении и на узел-отправитель загружаемых данных она не выполняется. Права на технические регистры БСП пользователям не нужны.

Связанные объекты должны входить в состав плана обмена узла, а их тип — быть разрешён для узла, иначе они не уйдут при выгрузке. Не вызывайте ПланыОбмена.ЗарегистрироватьИзменения в коде правила напрямую: код выполняется в безопасном режиме.

При изменении существующего объекта правило, как и типовые правила регистрации, выполняется до двух раз: по новому состоянию (ДанныеИБ — объект) и, если оно не прошло, по сохраненному в базе (ДанныеИБ — ссылка). Так узел узнает, что объект перестал подходить (например, документ распровели). Для объекта признак Проведен уже подставлен по режиму записи (проведение — Истина, отмена проведения — Ложь), поэтому правилу достаточно проверять ДанныеИБ.Проведен. Заявка дополнительной регистрации учитывается только из прогона по новому состоянию.

Пример: отправлять файлы заказа поставщику контрагента «РогаИКопыта» один раз, при проведении:

Если ДанныеИБ.Проведен
И ДанныеИБ.Контрагент = Справочники.nept_ВспомогательныеДанные.ЗначениеЭлемента("Контрагенты", "РогаИКопыта") Тогда
ФильтрПройден = Истина;
Запрос = Новый Запрос;
Запрос.Текст =
"ВЫБРАТЬ
| ПрисоединенныеФайлы.Ссылка КАК Ссылка
|ИЗ
| Справочник.ЗаказПоставщикуПрисоединенныеФайлы КАК ПрисоединенныеФайлы
|ГДЕ
| ПрисоединенныеФайлы.ВладелецФайла = &Ссылка
| И ПрисоединенныеФайлы.Размер > 0
| И НЕ ПрисоединенныеФайлы.ЭтоГруппа
| И НЕ ПрисоединенныеФайлы.ПометкаУдаления";
Запрос.УстановитьПараметр("Ссылка", ДанныеИБ.Ссылка);
Файлы = Запрос.Выполнить().Выгрузить().ВыгрузитьКолонку("Ссылка");
ПРО_ИсполняемыйКод.ЗарегистрироватьСвязанные(ДополнительнаяРегистрация, Файлы, Истина);
КонецЕсли;

Проверить правило можно в редакторе кода: команда «Выполнить на сервере» с выбранными данными и узлом покажет, какие объекты будут зарегистрированы, ничего не регистрируя.

Как это работает

  1. Вы настраиваете правила для конкретного узла обмена
  2. При обмене данными система проверяет ваши переопределения
  3. Если правило найдено — оно применяется вместо типового
  4. Если правило не найдено и переопределение включено — объект не регистрируется
